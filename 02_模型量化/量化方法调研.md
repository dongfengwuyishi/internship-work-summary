## 1. 常见量化路线（方法层面）


| 类型 | 简介 | 典型比特 |
| --- | --- | --- |
| **RTN** | Round-To-Nearest，最简单的量化方式，直接将权重四舍五入到目标比特，无需校准数据 | W4/W8 |
| **GPTQ** | 逐层权重量化，Hessian 近似最小化输出误差（PTQ） | W4 |
| **AWQ** | 按激活分布识别显著权重，对重要通道保留更高精度 | W4 |
| **SmoothQuant** | 把量化难度从激活「平滑」到权重，方便 W8A8 整型推理 | W8A8 |
| **GPTAQ** | GPTQ 改进，非对称校准减轻层间误差累积；**GPTQv2 为同方法的另一名称** | W4 |

### 2.2 部署与「下一代」压缩栈（与 AWQ/GPTQ 强相关）


| 框架 / 仓库                                                                      | 角色                          | 集成算法（官方 README） | 维护状态   | 最近推送（UTC）      |
| ---------------------------------------------------------------------------- | --------------------------- | ----------------- | ------ | -------------- |
| **[llm-compressor](https://github.com/vllm-project/llm-compressor)**         | 面向 vLLM 的压缩/量化流程与导出 | **Simple PTQ**（含 RTN 等朴素 PTQ）、**GPTQ**、**AWQ**、**SmoothQuant**、**AutoRound** | **活跃** | **2026-04-10** |

离线用 **llm-compressor** 按文档校准、导出后，用对应版本的 **vLLM** 直接加载推理即可；具体格式与算子支持以 [官方文档](https://docs.vllm.ai/projects/llm-compressor/en/latest/) 与 `compression_schemes` 说明为准。

### 2.3 说明

#### GPTQ 有多套仓库原因

- **IST-DASLab/gptq**：GPTQ 论文作者的**原始参考实现**，研究/教学性质，基本停更。
- **AutoGPTQ**：社区在原始实现基础上封装的**易用工具库**，一度是 HuggingFace 生态下 GPTQ 量化的事实标准。现已 **archived**，官方建议迁移到 GPTQModel。
- **GPTQModel**：从 AutoGPTQ fork 演进而来，目前**活跃维护**，支持更多硬件后端和推理栈，是当前社区主推的 GPTQ 工具链。
- **GPTAQ（[Intelligent-Computing-Lab-Panda/GPTAQ](https://github.com/Intelligent-Computing-Lab-Panda/GPTAQ)）**：**GPTQv2 与 GPTAQ 是同一方法**（仓库 README 写明后更名为 GPTAQ）。官方**论文复现**用本仓库；**GPTQModel** 侧仍保留 `v2=True` 等旧接口名，对应的就是 GPTAQ。

#### AWQ 侧类似

- **llm-awq**：MIT-HAN-Lab（AWQ 论文作者）的**研究代码**，偏论文复现。
- **AutoAWQ**：社区封装的易用库，已 **archived**；README 指向 vLLM `llm-compressor` 等作为后续方案。

#### 小结

论文作者出参考实现 → 社区包装成易用框架（AutoXXX） → AutoXXX 停维护后由新项目（GPTQModel / llm-compressor）接力。选型时认准**当前活跃维护的那个**即可。
